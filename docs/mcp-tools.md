Every user-scoped call forwards the signed-in user's own Splitt session to the backend, which enforces ownership and permissions. An OAuth connection is further limited to the scopes granted at sign-in (see Scopes below): a tool is listed and callable only when its scope was granted.

## Scopes

Every tool belongs to exactly one OAuth scope. Clients request scopes with the standard space-separated `scope` parameter; a client that sends none is granted all of them and the consent page says so. A refresh may narrow the grant (`scope` on the `refresh_token` grant) but never widen it. The operator API key has the `read` scope only; a verified raw backend JWT has every scope. Role checks still apply on top: granting `listings` to a renter account unlocks nothing.
